# способность: проверить-область

## Когда применять
Игрок тапнул/кликнул по месту на листе, которое считает ошибкой.

## Когда НЕ применять
Тап по UI (кнопки голосов, штамп) — это другие способности. Тап вне листа — игнор.

## Примеры
- Good: тап по лестнице без перил при активном правиле «перила обязательны» → ошибка засчитана, ASCII-подсветка, звук.
- Bad: засчитывать ошибку по правилу, которое ещё не активно на этом листе — это «угадайка» ([принцип 2](../../../idea/06-principles/README.md)).

## Модель зума и пана
- Лист больше экрана, показывается **окном** (вьюпорт); 2–3 фиксированные ступени зума (целые размеры клетки, см. [карту системы](../../01-обзор/карта-системы.md#системы-координат)).
- **Пан** — перетаскивание одним пальцем по листу; **тап** — короткое касание без смещения (> 8 px смещения = пан, не тап).
- **Зум** — кнопки `+`/`−` и двойной тап; pinch — только если не конфликтует с жестами Telegram (вертикальные свайпы отключены через `Platform`).
- Тап → `screenToCell(point, viewport)` (чистая функция, тесты) → ячейка листа → ошибка, чей хитбокс содержит ячейку; несколько → ближайший центр.

## Что может пойти не так
- Промах по мелкой области на телефоне → хитбокс ≥ 44 px при минимальном зуме гарантирует **валидатор** через минимальное расстояние между ошибками ([нерушимые правила](../../03-данные/правила-нерушимые.md)); риск — [продуктовый риск 3](../../../idea/07-risks/product.md), [архитектурный риск 1](../../07-нефункциональные/риски-архитектуры.md).
- Ложное срабатывание → небольшой штраф времени, не «залипающий» ([what-to-avoid](../../../idea/05-research/what-to-avoid.md)).
