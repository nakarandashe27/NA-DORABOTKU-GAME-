# Главный кирпич

## Список сущностей из idea
Лист (чертёж), правило проверки, ошибка на листе, штамп/вердикт, персонаж (ГАП, ИИ-стажёр, коллега), голос-навык, реплика, событие, сцена/глава, навык (значение), репутация (значение), сейв, игрок.

Они чётко делятся на две группы:
- **Контент** — то, что пишет автор, лежит в сборке, не меняется во время игры (листы, правила, ошибки, персонажи, реплики, события, главы).
- **Состояние** — то, что меняет игрок (прогресс, навык, репутация, пройденные листы, флаги сюжета).

## Решение: два кирпича (выбрано 2026-10-13)

### Кирпич 1 — `Запись контента`
```
{ id: "sheet.stairs-01", type: "sheet", props: {...} }
```
- `id` — строка с префиксом типа, уникальна во всём контенте.
- `type` — один из типов ниже.
- `props` — поля типа. Ссылки на другие записи — только через `id`. **id неизменяемы**: переименование — только через `renames.json` ([нерушимые правила](правила-нерушимые.md)).
- Тексты не внутри записи, а ключом в словарь локали: `text: "line.gap.stairs-01"` → `ru.json`.

### Кирпич 2 — `Сейв`
Один документ на игрока. Единственный формат — в [сущностях](сущности.md#кирпич-2--сейв-меняет-игрок--единственный-формат) (поля `v`, `playerId`, `rev`, `seed`, `skill`, `rep`, `results`, `flags`, `at`); копии сливаются, а не перезаписываются.
Ссылается на контент только через `id`.

## Список вариантов (кирпич 1)
| type | Ключевые props |
|---|---|
| `sheet` | слои `.art.txt` + `.mask.txt`, активные правила, лимит времени, лимит «слушаний» голосов |
| `rule` | что запрещено, как подаётся игроку («в лицо»), с какого листа активно |
| `defect` | на каком листе, символ в маске (координаты вычисляет сборка), какое правило нарушает |
| `character` | имя, обращение (ты/вы), набор реплик |
| `voice` | навык, характер, вероятность «соврать» |
| `line` | кто говорит, ключ текста, условие показа (`condition` — данные, не строка) |
| `event` | условие, последовательность реплик/действий (напр. приход ИИ-стажёра) |
| `chapter` | порядок листов, комната |
| `room` | рисунок комнаты, маска проходимости, точки интереса |
| `flag` | закрытый перечень флагов событий |

## Что я выигрываю
- **Один загрузчик и один валидатор** контента: проверка «все ссылки по id существуют» на весь контент разом — ловит битые листы до запуска.
- **Контент без кода**: новый лист = новый JSON, как и требует [принцип «соло-скоуп»](../../idea/06-principles/one-person-company.md).
- **Локализация**: все тексты по ключам → EN потом без переписывания.
- **Сейв маленький и версионируемый**: хранит только id и числа → влезает в Telegram CloudStorage (4096 символов на ключ), легко мигрировать по `schemaVersion`.

## Что я проигрываю
- `props` у разных типов разные → нужна схема на каждый тип (простая проверка при загрузке), иначе опечатки в JSON всплывут во время игры.
- ASCII-чертёж внутри JSON неудобно рисовать руками → решено: рисунок и маска ошибок — отдельные `.txt`-слои, координаты вычисляет сборка ([сущности](сущности.md)).
- Условия показа реплик и событий нужно выражать данными (`condition`), а не свободными выражениями — меньше выразительности, зато валидатор видит все ссылки.
Готов на это: контента мало (5 листов в MVP), а выигрыш в валидации и локализации большой.
