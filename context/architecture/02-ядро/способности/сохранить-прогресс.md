# способность: сохранить-прогресс

## Когда применять
Лист закрыт, событие сработало, приложение свёрнуто.

## Когда НЕ применять
Каждый кадр/тап — лишняя нагрузка; середина листа не сохраняется (лист короткий, рестарт дешёвый).

## Примеры
- Good: `rev + 1` → `SaveStore.save()` в localStorage и Telegram CloudStorage, асинхронно, без блокировки игры ([local-first](../../../idea/06-principles/local-first.md)).
- Good: при загрузке копии **сливаются** по правилам из [сущностей](../../03-данные/сущности.md) — пройденное не теряется, даже если одна копия старее.
- Bad: блокировать игру, ожидая ответа CloudStorage.

## Что может пойти не так
- Версия старее → цепочка миграций по `v`; перед миграцией — копия в `save.backup.v{N}`.
- Версия новее (откат сборки) → не трогать, читать только известные поля, не перезаписывать.
- Копия битая → бэкап в `save.backup.*`, слияние без неё.
- Браузер и Telegram не видят друг друга до шага 2 → «код сейва»: экспорт/импорт строкой со слиянием.
- Смена хостинга меняет origin и обнуляет localStorage → поэтому свой домен с первого дня ([деплой](../../07-нефункциональные/деплой.md)).
