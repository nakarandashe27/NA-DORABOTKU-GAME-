# Roadmap — «НА ДОРАБОТКУ»

## Правило: архитектура описывает целевую систему

Файлы архитектуры (`01-обзор` … `08-дорожная-карта`) — единый источник правды о том, КАКОЙ система должна быть по итогам текущего замысла (целевой чертёж), а не только снимок сегодняшнего кода. Каждый компонент / способность / сущность помечается статусом: ✅ реализовано (есть в коде) · 🔜 запланировано (решено, кода ещё нет) · 💡 гипотеза (требует решения/исследования).

Для частей со статусом ✅ источник истины — код: если документация расходится с уже написанным кодом, прав КОД — чините документацию. Для 🔜/💡 документация — это проектное решение, по которому код будет писаться.

Решение поменялось — правь сам файл, не оставляй устаревшее: документация, расходящаяся с замыслом, хуже её отсутствия.

Значимое решение (смена стека, изменение модели данных, сдвиг границ системы, новый или убранный модуль) дополнительно фиксируй короткой ADR-записью с датой и причиной в `context/architecture/06-решения/журнал-решений/` (создай папку, если её ещё нет). Журнал отвечает на «почему и когда поменялось», файлы архитектуры — на «какой система должна быть по замыслу».

Мелкие уточнения вноси прямо в файлы — журнал для них не нужен, их история и так лежит в git. Не перекраивай архитектуру без причины на ходу, но реальное новое решение всегда отражай в документации, а не прячь его «чтобы не нарушать правило».

**Плюс правило для AI-сессий** — из [тестирования](../07-нефункциональные/тестирование.md#правило-для-ai-сессий): этап без теста или команды проверки не закрывается; удалённое удаляется.

  - **Контекст из архитектуры:** [технологии](../05-стек/технологии.md), [карта системы → слои](../01-обзор/карта-системы.md#слои-зависимости-координаты), [тестирование → CI](../07-нефункциональные/тестирование.md)
  - **Критерий готовности:** CI зелёный на пустом проекте; тестовый импорт `platform` из `core` роняет ESLint.
  - **Сделано:** `npm run check` (tsc → eslint → vitest → build → knip); границы слоёв закреплены тестом `tools/layers.test.ts`. Playwright перенесён в этап 4 — там первый смоук.

- [x] **2. Платформа и порядок старта**
  - **Что делаем:** интерфейс `Platform` + реализации `browser`, `telegram` (SDK только внутри Telegram, таймаут 500 мс, `disableVerticalSwipes`, safe area), `fake`; `app` со стартом `platform → save → content → scene`.
  - **Контекст из архитектуры:** [карта системы → интерфейсы, порядок старта](../01-обзор/карта-системы.md#интерфейсы), [триггеры → запуск](../04-потоки/триггеры.md), [границы](../01-обзор/границы.md)
  - **Критерий готовности:** тест старта на `fake`; в браузере без доступа к telegram.org старт < 1 с.
  - **Сделано:** `platform/{types,detect,browser,telegram,fake}.ts`, `app/boot.ts`; обычная ссылка стартует за ~0 мс (SDK не грузится), при недоступном SDK — фолбэк в браузер за ~0,5 с с сохранением `startParam`. Диагностический экран показывает канал, viewport, safe area, хранилища.

- [x] **3. Раскладка и координаты**
  - **Что делаем:** `layout`: фиксированный набор целых размеров клетки, вьюпорт с паном/зумом, `screenToCell`, перенос слов.
  - **Контекст из архитектуры:** [карта системы → системы координат](../01-обзор/карта-системы.md#системы-координат), [проверить-область → модель зума](../02-ядро/способности/проверить-область.md)
  - **Критерий готовности:** unit-тесты `screenToCell` на DPR 1 / 2 / 2,75 и всех ступенях зума.
  - **Сделано:** `layout/grid.ts` (ступени зума 7/9/12 CSS-px, клетка = целые физические px, DPR округляется до сотых, пан с ограничением краёв, зум с якорем под пальцем), `layout/wrap.ts`; 16 тестов, включая DPR 2.0000000596.

- [x] **4. Рендер: буфер ячеек → WebGL2 и Canvas2D**
  - **Что делаем:** интерфейс `Renderer`, атлас моноширинного шрифта с кириллицей и псевдографикой, WebGL2 instanced, Canvas2D, потеря/восстановление контекста, флаг `?renderer=canvas`.
  - **Контекст из архитектуры:** [технологии → рендер, шрифт](../05-стек/технологии.md), [триггеры → потеря контекста](../04-потоки/триггеры.md), [риск 5](../07-нефункциональные/риски-архитектуры.md)
  - **Критерий готовности:** один буфер → одинаковые снимки в обоих бэкендах (Playwright — ставится на этом этапе, + шаг в CI); лист-заглушка рисуется.
  - **Сделано:** палитра 16 цветов, атлас с обрезкой глифов по клетке, WebGL2 (texelFetch, пиксель в пиксель) и Canvas2D дают diff = 0; потеря/восстановление контекста; ошибка шейдера → Canvas2D вместо чёрного экрана. e2e: `tests/e2e/render.spec.ts`. Шрифт пока системный моноширинный (ponytail в `render/atlas.ts`).

- [x] **5. Звук-минимум** (код и тесты; проверка на iPhone — в воротах 8)
  - **Что делаем:** `Audio` с автоматом `locked/running/suspended/interrupted`, `unlock()` по жесту, один «пик»; `Silent`-реализация; индикатор «звук выкл».
  - **Контекст из архитектуры:** [карта системы → интерфейсы](../01-обзор/карта-системы.md#интерфейсы), [триггеры → звук](../04-потоки/триггеры.md)
  - **Критерий готовности:** unit-тест автомата; на iPhone пик звучит после первого тапа и после возврата из фона.
  - **Сделано:** `audio/state.ts` (чистый автомат + тесты), `audio/audio.ts` (Web Audio; без AudioContext остаётся `locked` = беззвучно, отдельная Silent-реализация не нужна).

- [x] **6. Сейв: `content-schema` + `SaveStore`** (браузер проверен e2e; Telegram — в воротах 8)
  - **Что делаем:** формат сейва v1, `playerId`, `rev`, слияние копий (чистая функция), миграции с бэкапом, адаптеры `Local` и `Cloud`, `Remote`-заглушка, «код сейва» (экспорт/импорт).
  - **Контекст из архитектуры:** [сущности → сейв](../03-данные/сущности.md), [нерушимые правила → сейв](../03-данные/правила-нерушимые.md), [сохранить-прогресс](../02-ядро/способности/сохранить-прогресс.md)
  - **Критерий готовности:** тесты слияния и миграции на фикстурах; сейв переживает перезагрузку и сворачивание в Telegram.
  - **Сделано:** `content-schema/src/save.ts` (формат v1, migrate, mergeSaves, checksum), `app/save-store.ts` (load/merge/backup, write rev+1, код сейва). `Remote`-заглушку не делали — появится вместе с сервером шага 2. e2e: `tests/e2e/save.spec.ts`.

- [ ] **7. Деплой**
  - **Что делаем:** GitHub Pages + свой домен (CNAME), `base: '/'`, деплой только после зелёного CI, хранение ассетов 2–3 прошлых сборок, перезагрузка при 404, версия сборки на экране ошибки; бот в @BotFather с URL домена.
  - **Контекст из архитектуры:** [деплой](../07-нефункциональные/деплой.md), [безопасность](../07-нефункциональные/безопасность.md)

  - **Сделано (код):** `.github/workflows/deploy.yml` (после зелёного CI → ветка `gh-pages`), `tools/keep-assets.mjs` (+ тест), восстановление при 404 в `index.html`, хеш сборки на экране ошибки. Первый деплой прошёл (CI и Deploy зелёные).
  - **Ждёт пользователя:** включить Pages (Settings → Pages → ветка `gh-pages`), создать бота в @BotFather с URL игры, купить домен (тогда `BASE_PATH=/` + CNAME).

- [ ] **8. 🚦 Ворота скелета: устройства, читаемость, РФ**

  - **Контекст из архитектуры:** [тестирование → ворота](../07-нефункциональные/тестирование.md#ворота), [метрики](../../idea/04-mvp/success-metrics.md), [скоуп](../../idea/04-mvp/scope.md)

## Фаза B — Демо (проверка чертежа + ИИ-стажёр)

- [ ] **9. Контент-пайплайн и валидатор**
  - **Что делаем:** загрузка записей `{id,type,props}`, разбор слоёв `.art.txt`/`.mask.txt` → `area`, `cols/rows`; тип `condition`; `renames.json`; `ru.json` с шаблонами и множественным числом; все проверки из нерушимых правил, включая минимальное расстояние между ошибками и покрытие атласа.
  - **Контекст из архитектуры:** [главный кирпич](../03-данные/главный-кирпич.md), [сущности](../03-данные/сущности.md), [нерушимые правила](../03-данные/правила-нерушимые.md), [схема связей](../03-данные/схема-связей.md)
  - **Критерий готовности:** сломанный лист (сдвинутая маска, исчезнувший id, текст длиннее экрана) роняет CI с понятным сообщением.

- [ ] **10. Механика листа в ядре**
  - **Что делаем:** сцена `sheet`: активные правила, тап → ошибка (ближайший центр), штрафы без «залипания», таймер на `dt` ≤ 100 мс с паузой, штамп СОГЛАСОВАНО/НА ДОРАБОТКУ (идемпотентно), итоги и реплики ГАПа, сеяный PRNG.
  - **Контекст из архитектуры:** [проверить-область](../02-ядро/способности/проверить-область.md), [поставить-штамп](../02-ядро/способности/поставить-штамп.md), [триггеры](../04-потоки/триггеры.md), [принципы](../../idea/06-principles/README.md)
  - **Критерий готовности:** golden run: записанная последовательность тапов даёт одинаковый итог и сейв.

- [ ] **11. Экран листа**
  - **Что делаем:** отрисовка листа во вьюпорте, пан/зум, подсветка найденных ошибок, правило «в лицо» при вводе, штамп и ругань ГАПа глифами `#@%!`, реплики в 1–2 строки.
  - **Контекст из архитектуры:** [характер](../02-ядро/характер.md), [карта системы → координаты](../01-обзор/карта-системы.md#системы-координат)
  - **Критерий готовности:** лист проходится пальцем на бюджетном Android без промахов; Playwright-смоук на 360×640.

- [ ] **12. Голоса-навыки**
  - **Что делаем:** «Черчение», «BIM», «Умение казаться занятым»: лимит «слушаний» на лист, подсказки-зацепки из `defect.hints`, ложь через PRNG, бесплатные комментарии в ключевых моментах.
  - **Контекст из архитектуры:** [послушать-голос](../02-ядро/способности/послушать-голос.md), [сущности → voice](../03-данные/сущности.md)
  - **Критерий готовности:** тест: при той же попытке голос врёт одинаково.

- [ ] **13. Контент демо**
  - **Что делаем:** 3–5 листов с нарастанием правил (лестница без перил, дверь в стену, отметка, штамп…), реплики ГАПа на все исходы, тексты голосов.
  - **Контекст из архитектуры:** [золотая сцена](../../idea/04-mvp/one-killer-feature.md), [характер](../02-ядро/характер.md), [what-to-steal](../../idea/05-research/what-to-steal.md)
  - **Критерий готовности:** валидатор зелёный; автор сам прошёл все листы без подсказок разработчика.

- [ ] **14. Сцена ИИ-стажёра**
  - **Что делаем:** `cutscene` поверх стека сцен, событие по `condition`, дуэль на одном листе: ИИ «сдаёт» за 2 секунды с абсурдной ошибкой (санузел в шахте лифта), ГАП выбирает ИИ; флаг `flag.ai_arrived`.
  - **Контекст из архитектуры:** [запустить-событие](../02-ядро/способности/запустить-событие.md), [карта системы → сцены](../01-обзор/карта-системы.md#сцены), [золотая сцена](../../idea/04-mvp/one-killer-feature.md)
  - **Критерий готовности:** событие не прерывает лист посередине и повторно не запускается.

- [ ] **15. Звук демо**
  - **Что делаем:** процедурные SFX: штамп, тиканье, гул плоттера, «бормотание» персонажей.
  - **Контекст из архитектуры:** [технологии → звук](../05-стек/технологии.md), [скоуп](../../idea/04-mvp/scope.md)
  - **Критерий готовности:** без щелчков при нагрузке рендера на бюджетном Android; игра полностью играбельна без звука.

- [ ] **16. Поделиться моментом**
  - **Что делаем:** Telegram: `openTelegramLink` на `t.me/share/url` со ссылкой `?startapp=<sheetId>` (`shareMessage` — только с сервером, шаг 2); браузер: Web Share API или копирование ссылки; открытие листа по `startParam`.
  - **Контекст из архитектуры:** [поделиться-моментом](../02-ядро/способности/поделиться-моментом.md), [безопасность → недоверенный ввод](../07-нефункциональные/безопасность.md)
  - **Критерий готовности:** ссылка в чате открывает тот же лист у другого человека в обоих каналах.

- [ ] **17. 🚦 Плейтест демо**
  - **Что делаем:** 10 знакомых архитекторов; замер технических метрик.
  - **Контекст из архитектуры:** [метрики](../../idea/04-mvp/success-metrics.md)
  - **Критерий готовности:** ≥ 5/10 прошли все листы, ≥ 3/10 переслали; ≥ 50 fps на среднем Android; загрузка < 2 с. Нет — разбор и решение до MVP.

## Фаза C — MVP (вертикальный срез)

- [ ] **18. Комната офиса**
  - **Что делаем:** `room` из `.art.txt` + `.walk.txt`, камера за персонажем, ходьба: тап-в-точку (телефон) и клавиатура (десктоп), точки интереса (стол → лист, NPC → диалог); фоновая ASCII-живость (плоттер, мерцание).
  - **Контекст из архитектуры:** [сущности → room](../03-данные/сущности.md), [карта системы → сцены](../01-обзор/карта-системы.md#сцены), [сессия игрока](../../idea/02-vision/day-in-the-life.md)
  - **Критерий готовности:** из комнаты открывается лист и возвращается обратно с сохранением позиции.

- [ ] **19. NPC и диалоги**
  - **Что делаем:** ГАП (на «ты») и ИИ-стажёр (на «вы») в комнате, реплики по `condition`.
  - **Контекст из архитектуры:** [характер](../02-ядро/характер.md), [сущности → character, line](../03-данные/сущности.md)
  - **Критерий готовности:** реплики не вылезают за экран (валидатор) и меняются от флагов.

- [ ] **20. Прогресс**
  - **Что делаем:** навык и репутация у ГАПа, влияние на реплики и исход дуэли; экран «код сейва».
  - **Контекст из архитектуры:** [сущности → сейв](../03-данные/сущности.md), [права доступа](../02-ядро/права-доступа.md)

- [ ] **21. Адаптивное качество**
  - **Что делаем:** бюджет кадра 16 мс на 360×640, понижение качества анимаций с гистерезисом, `performance_class` Telegram как подсказка.
  - **Контекст из архитектуры:** [триггеры → кадр дольше бюджета](../04-потоки/триггеры.md), [тестирование → матрица](../07-нефункциональные/тестирование.md)
  - **Критерий готовности:** ≥ 50 fps на бюджетном Android в комнате и на листе.

- [ ] **22. Аналитика-минимум** 💡
  - **Что делаем:** решить и сделать минимальный счётчик событий без персональных данных: старт, лист пройден, сцена ИИ, возврат на следующий день.
  - **Контекст из архитектуры:** [технологии → аналитика](../05-стек/технологии.md), [безопасность](../07-нефункциональные/безопасность.md), [метрики](../../idea/04-mvp/success-metrics.md)
  - **Критерий готовности:** видна доля дошедших до сцены ИИ и D1.

- [ ] **23. Запуск MVP и гейт холодной аудитории**
  - **Что делаем:** публикация бота и ссылки в профильных каналах; сбор метрик 2 недели.
  - **Контекст из архитектуры:** [пресс-релиз](../01-обзор/пресс-релиз.md), [премортем идеи → вердикт](../../idea/07-risks/README.md)
  - **Критерий готовности:** решение по kill-критерию: ≥ 50% холодной аудитории доходят до сцены ИИ и ~1000 запусков → планировать шаг 2; нет → проект остаётся визиткой или разворачивается.
