# Сущности

Два кирпича ([главный-кирпич](главный-кирпич.md)): **Запись контента** `{id, type, props}` и **Сейв**. Ниже — `props` по типам. Ссылки — только по `id`, у каждой связи хранится **одна сторона** (вторая вычисляется при загрузке, см. [схему связей](схема-связей.md)). Тексты — ключи локали. Пересмотрено после [премортема архитектуры](../07-нефункциональные/риски-архитектуры.md) (риски 2, 4, 6, 9, 10).

## Кирпич 1 — контент (только чтение, лежит в сборке)

| Сущность (`type`) | Назначение | Хранимые поля | Вычисляется сборкой |
|---|---|---|---|
| `chapter` | порядок прохождения | `sheets[]` (по порядку), `room` | — |
| `room` | комната офиса (MVP — одна) | `art` (путь к `.art.txt`), `walk` (`.walk.txt` — маска проходимости), `spots[]` {символ маски → действие: открыть лист / поговорить с NPC} | `cols`, `rows` |
| `sheet` | лист-чертёж | `art` (`.art.txt`), `mask` (`.mask.txt`), `rules[]` (активные), `timeLimitSec`, `listens`, `outcomeLines` {`approvedClean`, `approvedDirty`, `rejected`} | `cols`, `rows`, список ошибок, глава |
| `rule` | правило проверки | `text` (ключ), `introLine` (подача «в лицо») | `firstSheet` (первый лист, где активно) |
| `defect` | ошибка на листе | `sheet`, `mark` (символ в маске: `1`–`9`, `a`–`z`), `rule`, `hints` {voiceId → ключ текста} | `area` (клетки из маски), центр |
| `character` | персонаж | `name` (ключ), `address` (`ty`/`vy`), `color`, `room`, `pos` {x, y} в клетках комнаты | — |
| `voice` | голос-навык | `name` (ключ), `lieChance` (0 ≤ p < 0.5) | — |
| `line` | реплика | `speaker` (character или voice), `text` (ключ), `when` (`condition`, опц.) | — |
| `event` | сюжетное событие | `when` (`condition`), `steps[]` (реплика / сцена / установить флаг), `flag` (какой флаг ставит по завершении) | — |
| `flag` | закрытый перечень флагов | `id` (`flag.ai_arrived`), описание | — |

### Формат рисунка листа (риск 2)
Лист — это **слои одинакового размера** рядом с JSON:
```
content/sheets/stairs-01.json
content/sheets/stairs-01.art.txt    ← сам чертёж
content/sheets/stairs-01.mask.txt   ← '.' = пусто, '1'..'9','a'..'z' = номер ошибки (поле defect.mark)
```
- Координаты ошибок **не пишутся руками** — сборка читает маску и строит `area` каждой ошибки. Сдвинул рисунок, не сдвинув маску → валидатор ловит (клетка маски над пустым символом рисунка).
- `cols/rows` — из реального размера файла, не из JSON.
- Файлы: UTF-8 без BOM, LF, без табов, все строки одной длины (дополняются пробелами), см. [нерушимые правила](правила-нерушимые.md). Рисуется в любом моноширинном редакторе; отдельный редактор не делаем, пока листов < 20.
- Комната — тот же принцип: `.art.txt` + `.walk.txt` (проходимость, символы точек интереса).

### Тип `condition` (риск 6)
Условия — данные, а не строки-выражения. Закрытый набор операций:
```
{ "all": [ ... ] } | { "any": [ ... ] } | { "not": {...} }
{ "flag": "flag.ai_arrived" } | { "done": "sheet.stairs-05" } | { "repAtLeast": ["character.gap", 2] }
```
Валидатор обходит условие и проверяет все ссылки так же, как обычные поля.

### Локализация (риск 10)
`ru.json`: ключ → строка-шаблон с именованными подстановками и формами множественного числа (`{n, plural, one {# лист} few {# листа} many {# листов}}`, формат ICU MessageFormat, без библиотеки — свой минимальный разбор). Валидатор проверяет длину реплики в клетках сетки и покрытие атласа.

**Отсутствуют сознательно:** «навык» как запись (в MVP он один — число в сейве), «игрок» (на шагах 0–1 аккаунтов нет, только анонимный `playerId`), «штамп» (значение результата листа).

## Кирпич 2 — сейв (меняет игрок) — единственный формат

```json
{
  "v": 1,
  "playerId": "p_8f3k2…",
  "rev": 17,
  "seed": 912384,
  "skill": 3,
  "rep": { "character.gap": -1 },
  "results": { "sheet.stairs-01": { "found": ["defect.stairs-01.rail"], "stamp": "approved", "attempt": 2 } },
  "flags": ["flag.ai_arrived"],
  "at": { "chapter": "chapter.1", "scene": "office" }
}
```

| Поле | Назначение | Правило слияния двух копий (local ⇄ CloudStorage ⇄ код сейва) |
|---|---|---|
| `v` | версия схемы → цепочка миграций `v1→v2→…` | сначала обе копии мигрируются до текущей |
| `playerId` | анонимный id устройства (случайный, создаётся при первом запуске); шов для шага 2 | разные id → это разные игроки: спросить, какой оставить (единственный случай) |
| `rev` | счётчик сохранений (вместо времени устройства как арбитра) | `max` |
| `seed` | зерно PRNG игрока | из копии с большим `rev` |
| `skill` | значение навыка | `max` (прогресс монотонный) |
| `rep` | репутация по персонажам | из копии с большим `rev` (может падать — не монотонна) |
| `results` | итоги листов | объединение по листу; при конфликте — запись с большим `attempt` |
| `flags` | сработавшие события | объединение (логическое «или») |
| `at` | где игрок сейчас | из копии с большим `rev` |

Слияние — чистая функция в `content-schema`, тесты на фикстурах. Размер: id в сейве — полные строки, пока сейв < 3 КБ; при приближении к лимиту CloudStorage (4096 символов на ключ) — переход на короткие индексы через миграцию.

### Мост браузер ⇄ Telegram (риск 4)
До шага 2 копии в браузере и в Telegram не знают друг о друге. Мост — **«код сейва»**: экспорт сейва строкой (base64 + контрольная сумма) и импорт в другом канале, со слиянием по правилам выше.
