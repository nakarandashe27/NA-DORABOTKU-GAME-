# Деплой

Ответ на [архитектурные риски 4 и 8](риски-архитектуры.md).

## Куда
- **GitHub Pages + свой домен** (CNAME). Домен — [заполнить: имя; покупка — решение и действие пользователя]. Без своего домена путь вида `/<repo>/` и смена хостинга меняют origin → игроки теряют localStorage-сейвы, а URL Mini App в @BotFather приходится менять.
- План Б (замер из РФ провален): та же сборка на российский хостинг статики, домен переключается в DNS — origin и сейвы не меняются ([технологии](../05-стек/технологии.md)).

## Как
- GitHub Actions: деплой только после зелёного CI ([тестирование](тестирование.md)).
- Vite `base: '/'` (свой домен); все пути к атласу и контенту — через импорт или относительно `base`, не абсолютные строки.
- Версия сборки = короткий хеш коммита; показывается на экране ошибки и в «коде сейва».
- **Старые файлы живут дольше одного деплоя**: при публикации в ветку `gh-pages` хешированные ассеты прошлых 2–3 сборок не удаляются (подчистка — по возрасту). Иначе Telegram WebView с закэшированным `index.html` получает 404 → белый экран.
- `index.html` маленький; при 404 на ассет — одна перезагрузка (флаг в sessionStorage, см. [триггеры](../04-потоки/триггеры.md)), второй раз — экран «обнови игру».
- Кэш заголовками GitHub Pages не управляется (~10 мин) — отсюда хеши в именах файлов.
