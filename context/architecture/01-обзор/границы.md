# Границы

## Что внутри системы (наша ответственность)
- Весь клиент игры: цикл, механика проверки, диалоги, прогресс, рендер, звук.
- Контент: листы, правила, тексты.
- Сейв на устройстве и его формат (версия схемы — чтобы обновление игры не ломало старые сейвы).
- Шаг 2: один сервер сейвов + одна база + бот.

## Что снаружи (используем как сервис, доверяем)
- Статический хостинг (раздаёт файлы).
- Telegram: клиент и WebView, Mini Apps SDK, CloudStorage, share; шаг 2 — Bot API.
- Браузер / WebView: WebGL2, Web Audio, localStorage.

## Граница доверия
- **От пользователя (опасно):** ввод в игре — безопасен, это тапы. Сейв на устройстве игрок может подделать — на шагах 0–1 это не важно (одиночная игра, рейтингов нет). На шаге 2 сервер **не доверяет** присланному прогрессу без проверки `initData` (HMAC) и базовой валидации. Параметр `start_param` из ссылки — недоверенный, только как подсказка (номер листа).
- **От внешних сервисов (может упасть):** Telegram может быть недоступен (РФ) → игра обязана работать без SDK и без CloudStorage. WebView может не дать WebGL2 → fallback Canvas2D. AudioContext может не стартовать → игра без звука, но работает.
- **От нас (доверяем):** контент в сборке, код игры.

## Правило масштаба
Шаги 0–1: ноль серверов. Шаг 2: один сервер, одна база, один деплой. Никаких микросервисов.
